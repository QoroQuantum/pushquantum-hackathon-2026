## How the scores were found

- **Whole-day pair-move search** (`day_swap.py`; parallel driver `day_swap_parallel.py`), every instance.
  With the other days fixed, one whole day's official score is `v A v + Σ f_i(v_i)` (closed form
  `day_form`). At scale the unit budget binds on every day (a400: 100 of 100 units), so an improving move
  must take a unit from one asset and give it to another; steepest descent applies the best of all single
  value changes and all ±1 × ±1 pair moves (numba; ±2 steps are redundant because the objective is convex
  along lines). Per-day iterated local search on top: small kicks, *ruin* (zero 10–40% of the held
  positions) and *shrink* kicks for hedged long/short books, threshold acceptance, and multi-day moves (copy
  or drop the same positions on 2–4 consecutive days, then alternating exact day descents; a010_t15_s02
  λ1e-3 needs a 3-day one). a400 runs as contiguous day shards in parallel processes; a shard's days are kept
  only if the official score improves. Every accepted move is re-scored with the referee.
- **Grid driver** (`grid_runs.py`): day_swap from the empty portfolio for every (instance, λ, seed), several
  seeds each, then warm-started polish rounds with new seeds on whatever is still above its best-known value.
- **Exact dynamic program for a010** (`exact_dp.py`). Days interact only through the trading cost between
  consecutive days, and with a budget of 4 units a day has 8,341 feasible holdings, so a shortest path over
  days is exact (numba min-plus, ~0.2 s per instance). The DP value and the referee are checked to differ by
  one constant on random solutions of every instance before the result is trusted.
- **Recombination** (`recombine_runs.py`): the same DP restricted to the day holdings that our runs of an
  instance use, i.e. the best mix of days across runs (the kit's "combine samples" stitching), then polish.
- **Hybrid quantum loop** (`warm_day_qaoa.py loop`): one hand-in file,
  `po_a050_t10_s00_b020_l1e-3.sol`, comes from 8 rounds of 150-qubit warm-start QAOA on Qoro's cloud followed
  by day_swap polish (see `QUANTUM_STORY.md`; the polish does most of the work).

**Partitioning.** We cut by period: one block = one whole day with every asset. Cutting by asset group
drops 77–98% of the QUBO's coupling weight, cutting by period 0–1% (table in `QUANTUM_STORY.md`), and the
solvers agree: asset-group blocks of 6–12 assets barely improved a solution, whole-day blocks did.

## Reproduce

```bash
python exact_dp.py                                                       # all 64 a010 instances, exact
python grid_runs.py run --sizes a050_t15 a050_t10 --seeds 0 1 --time 180 --warm
python grid_runs.py polish --window 4 --seeds 2 3 4 --time 240 --stall 90
python recombine_runs.py --match a050
python day_swap_parallel.py --init <a400 start>.sol --workers 6 --round 240 --rounds 10 --window 4
python make_handin.py --dirs results/grid results/grid_polish results/grid_polish2 results/grid_fresh \
    results/exact_dp results/recombine results/recombine2 results/warm_day_qaoa   # re-score, copy, RESULTS.md
```

Re-check a file:

```python
import qoblib_tools as qt
h, pos = qt.read_portfolio_solution("handin/po_a050_t15_s00_b020_l1e-3.sol")
m = qt.PortfolioModel(qt.load_portfolio_instance(h["instance"]), budget=int(h["budget"]), lam=h["lambda"])
print(m.score(pos))
```
