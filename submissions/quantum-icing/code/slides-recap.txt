05 | An optimization run, end to end

QUANTUM OPTIMIZATION WITH DIVI

01. Formulate. Objective plus penalties as a QUBO, with constraints added in Divi.
02. Check and split. Characterize the QUBO, then partition it into blocks that fit
    your qubits.
03. Solve. QAOA, blind or warm-started, or PCE on each block, run in parallel.
04. Stitch and repair. Recombine the blocks, fix broken constraints, polish with
    local search.
05. Score. Official QOBLIB objective with qoblib_tools.py, then write the .sol file.

07 | Why partition

SCALING QUANTUM OPTIMIZATION

- 16 GiB: Memory for one 30-qubit statevector. Every extra qubit doubles it.
- ~36,000: Binary variables in the largest portfolio instance of the challenge.
- 552: Binary variables in the largest network-design instance.

Two ways to fit a large problem onto small hardware
- Compress: Pauli Correlation Encoding (PCE) stores many binary variables in
  correlations between fewer qubits.
- Partition: Split the QUBO into blocks, solve each block, then stitch the results
  together. This is the focus of the challenge.

Statevector memory assumes 16-byte complex amplitudes: 2^30 × 16 bytes = 16 GiB.

08 | Partitioning a QUBO

SCALING QUANTUM OPTIMIZATION

1. QUBO as a graph or a binary quadratic model. Each variable is a node; each
   non-zero coupling is an edge.
2. Cut it into blocks that fit. Keep every block within your qubit budget, and
   keep strong couplings inside blocks.
3. Solve the blocks in parallel. The blocks are independent, so they run side by
   side on CPUs, GPUs and QPUs.

[The coupling matrix shows three diagonal squares labeled Block 1, Block 2 and
Block 3. The legend identifies diagonal squares as “Coupling inside a block” and
off-diagonal marks as “Cut coupling.”]

Every cut coupling is an interaction no block sees. Fewer, weaker cuts leave less
for stitching to repair.
Ways to cut: problem structure, spectral or METIS graph partitioning, community
detection, overlapping blocks.

09 | Stitching block solutions back together

SCALING QUANTUM OPTIMIZATION

Four approaches, from cheapest to most thorough. They combine well.

01. Concatenate. Join the block solutions as they are. Fast, but every cut
    coupling is ignored.
02. Clamp and iterate. Fix the other blocks, fold the cut couplings into this
    block's linear terms and re-solve. Repeat until stable.
03. Combine samples. Keep several samples per block and search their combinations
    on the full objective.
04. Repair and polish. Restore any broken constraints, then run classical local
    search on the full problem.

Score on the official objective, not the QUBO energy. A low energy does not
guarantee a feasible, high-scoring solution, because penalty weights distort the
objective. Score with qoblib_tools.py and compare every result with the notebooks'
classical baselines.

11 | QOBLIB: the benchmark behind the challenge

THE CHALLENGE

The Quantum Optimization Benchmarking Library: ten problem classes that
state-of-the-art classical solvers find hard, with open instances and results.
Any classical, quantum or hybrid method can compete.

- 10 problem classes, the “Intractable Decathlon”.
- 1,264 instances across the ten classes.
- 100–10k variables where the classes turn hard for classical solvers.

Each class includes
- Instances of growing size.
- Model descriptions, such as LP and QUBO files.
- Optimal or best-known solutions.
- A checker for feasibility and objective.

Who built it: the Quantum Optimization Working Group, started by IBM Quantum
and partners in 2023, led with Zuse Institute Berlin and Purdue. Published in
Nature Computational Science (2026).

What it means for you: your result is judged against QOBLIB's best published
results, and a better one can be submitted as a new record.

Sources: QOBLIB repository, github.com/ZIB-AOPT/QOBLIB; Koch et al., Nature
Computational Science 6, 653–671 (2026); instance count from Quantum Computing Report.

14 | Multi-period portfolio optimisation

PROBLEM A · QOBLIB 06

- You decide: How many units of each asset to hold, long or short, in each period.
- Objective: Balance expected return against risk, net of the transaction costs
  of changing positions.
- Constraints: 0 to 3 units per asset and direction, plus capital and budget
  limits each period.
- Size: Integer holdings become groups of binaries: 58 to ~36,000 variables.

Where the couplings are
- Risk links assets within the same period.
- Transaction costs link each asset to itself in the next period.
- Cutting by period drops transaction-cost links; cutting by asset group drops
  risk links. Measure which loses less.

Notebook 01: official model → QUBO → classical baseline → PCE and partitioned
QAOA → solution file

15 | Network design

PROBLEM B · QOBLIB 08

- You decide: Which directed links to build between n nodes: exactly 2 out and
  2 in per node.
- Then: Route the traffic demand between every pair of nodes over the links you built.
- Objective: Minimise the load on the busiest link.
- Size: One binary per possible link, n(n−1): 20 at 5 nodes, 552 at 24 nodes.

How the work is split
- Quantum: a topology QUBO, with the degree rules as Divi LinearConstraints.
- Classical: an exact routing LP scores each sampled topology.
- Each degree rule ties together one node's row or column of links. A cut through
  a row leaves that rule for stitching to enforce.

Notebook 02: topology QUBO → sample → route with LP → score → solution file

16 | How solutions are scored

THE CHALLENGE

PROBLEM A · PORTFOLIO OPTIMISATION
- Rules the referee checks: 0 to 3 units per asset and direction; capital and
  budget limits in every period.
- Score: Risk minus return, plus transaction, short-selling and liquidation costs,
  minus interest on cash.

PROBLEM B · NETWORK DESIGN
- Rules the referee checks: Every node has exactly 2 links out and 2 in; flows
  deliver all the demand over chosen links only.
- Score: The largest total flow on any link, in units of 1/1000.

Quality: your gap to the best-known value
gap = (score − best) / |best|
0% matches the best-known value; below 0% beats it. Example: −69,169 against
−69,482 is a 0.45% gap.

Scale
The binary variables in the instance you solve, and the qubits in your largest
quantum program.

Lower is better for both problems. A solution that breaks a rule doesn't count,
and the referee recomputes the objective from your .sol file.

19 | Setup: Colab or your own machine

THE CHALLENGE

In Google Colab
1. Open a notebook with its Open in Colab badge.
2. Add a Colab secret named QORO_API_KEY and switch on notebook access.
3. Run the first setup cell. If it installs Divi 0.16.2, restart the session and
   run again.
4. File › Save a copy in Drive to keep your changes.

On your own machine

    git clone https://github.com/QoroQuantum/pushquantum-hackathon-2026.git
    cd pushquantum-hackathon-2026
    pip install "qoro-divi[qubo-decompose,jupyter]==0.16.2"

Python 3.11 or newer. Put QORO_API_KEY="your key" in a .env file next to the
notebooks; .gitignore keeps it out of commits.

PennyLane code.

No API key yet? Everything runs on the local simulator, and cloud-only cells
(the Characterization Service) print Skipped.
